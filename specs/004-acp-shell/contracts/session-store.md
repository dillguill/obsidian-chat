# Contract: Host-Owned Session Store

**Status**: Design contract for spec `004-acp-shell` (approved 2026-11-07).
**Applies to**: `plugin/src/session/record.ts`, `store.ts`, `resume.ts`, `digest.ts`, `migrate.ts`.
**Spec**: FR-021, FR-053…FR-070; continuity FR-060…FR-067; migration FR-059/FR-069.

The conversation record is the single source of truth for history, the transcript view, the raw ACP
view, continuity, and the digest. It is host-owned, append-only, and never a Markdown note.

## 1. Location and files

Default root: the vault folder `.chat/sessions/` (a setting; hidden from the ordinary note surface).

| File | Purpose |
|---|---|
| `<sessionId>.jsonl` | The session record: one header line, then append-only entry lines |
| `index.json` | Optional rebuildable cache of session summaries (derived from headers); never canonical |
| `registry.json` | Host session registry used for reattach (sessionId → device, harness identity, cwd, lastSeq, state) |
| `migration.json` | Legacy-note import ledger (note path + hash + imported sessionId) for idempotency |

Session ids are opaque, generated by the store, and never contain device or harness names. A record
belongs to exactly one device (the one that created the session); the host never serves it to
another device.

## 2. Record format (JSONL)

- UTF-8, one JSON object per line, no pretty printing, no base64. The first line is the header; every
  later line is one entry. Lines are independent: a reader can skip a malformed line without losing
  the rest.
- Sequence numbers are assigned by the store, monotonically increasing per session, starting at 1.
  They are the replay/dedupe key and are mirrored into ACP `_meta` on replay (see
  `contracts/host-transport.md` §4).
- Timestamps are epoch milliseconds; `turn` is a monotonically increasing turn number.
- A version field (`v: 1`) is present in the header and on every entry that can evolve. Readers MUST
  tolerate unknown entry kinds/fields by skipping or rendering them raw, never by failing the
  session.

### 2.1 Header (first line, written once)

```json
{ "kind": "header", "v": 1, "sessionId": "...", "deviceId": "...", "title": "...",
  "createdAt": 0, "updatedAt": 0, "lastSeq": 0,
  "harness": { "commandLabel": "<redacted display>", "commandFingerprint": "...", "cwd": "/abs/vault",
               "protocolVersion": 1, "agentName": "...", "agentVersion": "...",
               "capabilities": { "loadSession": false, "resume": false } },
  "harnessSessionId": "...", "resume": { "state": "unknown|resume-capable|load-only|digest-only|fresh-only",
               "reason": "..." },
  "modes": { "currentModeId": "...", "availableModes": [ ... ] },
  "config": { "optionId": "value", ... } }
```

`commandLabel` is a **redacted display form** — the raw command is not stored, because a user could
embed a token in it; the full command lives only in settings. `commandFingerprint` is a stable hash of the normalized harness command plus the working directory;
`cwd` is stored verbatim because ACP resume/load requires the same cwd. The capability snapshot is
what continuity decisions and the UI use without re-handshaking.

### 2.2 Entries

| Kind | Key fields | Purpose |
|---|---|---|
| `prompt` | `seq, ts, turn, blocks` | The user turn sent to the harness (bounded text/context blocks; images by name/type only) |
| `update` | `seq, ts, turn, sessionUpdate, payload` | One ACP `session/update` notification, mapped minimally and stored; unknown kinds stored with their raw payload |
| `permission_request` | `seq, ts, turn, requestId, toolCall, options` | The harness's permission request |
| `permission_response` | `seq, ts, requestId, outcome` | `selected(optionId)` or `cancelled` |
| `turn` | `seq, ts, turn, stopReason, interrupted` | The prompt's resolution (the only turn terminator; **never** named `turn_end`, which is the deleted SSE envelope) |
| `resume` | `seq, ts, method, result, reason?` | An attempted resume/load/digest/fresh decision and outcome |
| `meta` | `seq, ts, title?` | Harness session-info/title update or user rename |
| `error` | `seq, ts, scope, message` | Visible failure (transport, MCP unavailable, store degraded) |

Entries store protocol data, not rendered UI state. The transcript is a projection (§4).

## 3. Append, durability, and repair

- Writes are **append-only**: never rewrite earlier lines, never reorder, never truncate on update.
  The store appends through `app.vault.adapter.append` (present on `FileSystemAdapter` and
  `CapacitorAdapter`; no read-modify-write fallback is needed). Serialize appends through one
  promise chain per session; no concurrent writes to the same file.
- Create the record with `adapter.exists` → `adapter.mkdir` each missing segment →
  `adapter.write(headerLine + "\n")`; do not use `vault.create` for the hidden folder (the note
  index may not know it).
- Each entry is serialized and written as one complete line followed by `\n`, awaited per entry; a
  crash may lose the last unflushed entry but must not corrupt earlier entries.
- On open, a trailing partial line (no newline) is ignored and reported as a degraded tail; before
  the next append, write a single `\n` so the fragment becomes an isolated skipped line (still
  append-only). The reader never fails the whole session for it. A malformed interior line is skipped
  and counted; the session is marked degraded in its summary for the UI. A bad header is reported as
  unreadable and never fabricated into an empty session.
- `lastSeq` in the header is best-effort (updated at turn boundaries); the authoritative last
  sequence is the tail entry's `seq`. If the registry's lastSeq is ahead of the tail, mark the
  session degraded (possible external truncation/sync conflict).
- External modification (sync conflict, manual edit) is detected by a changed tail/sequence; the
  reader surfaces a degraded state and never rewrites the file to "fix" it. Ignore Obsidian Sync
  conflict files (`*.sync-conflict-*`); never merge them. The host is the only writer in v1.
- Deleting a session (user action) removes its record and registry entry after confirmation; no
  Markdown note is created or deleted.

## 4. Reading and projections

- **Header scan** (session list): read only the first line of each record; derive title, updated
  time, device, resume state, and seq. `index.json` is a cache at most; if it disagrees with headers,
  headers win.
- **Transcript projection**: deterministic from entries — prompts and assistant/reasoning chunks
  become messages; tool updates become one tool-card per `toolCallId`; plan/usage/session-info
  become their panels; unknown/raw entries become generic raw rows. The projection never invents
  content and never renders a turn as complete without its `turn` boundary entry.
- **Raw view**: the per-turn "ACP updates" disclosure and the connection raw log read the same
  entries (the ACP/raw fields), bounded and lazily.
- **Digest input**: derived only from the record (see §6).
- Reading is streaming/lazy for long sessions; the UI never loads unbounded payloads eagerly.

## 5. Sequence, replay, and devices

- Replay to a remote device reads entries and emits them as ACP `session/update` notifications with
  `_meta: { "obsidian-chat/seq": n, "obsidian-chat/replay": true }`; live notifications carry the
  same `obsidian-chat/seq` without `replay`. Replay never appends new entries.
- The remote client dedupes by `obsidian-chat/seq`; `session/load` may request `sinceSeq` via `_meta`.
- Records are device-scoped; `session/list` returns only the requesting device's sessions.

## 6. Continuity, resume state, and digest

- Resume state is a function of the stored capability snapshot + current attach:
  `resume-capable` (harness `sessionCapabilities.resume`), `load-only` (top-level
  `agentCapabilities.loadSession`), `digest-only` (neither), `fresh-only` (identity mismatch, harness
  unreachable, or the record has no usable continuity material). The UI shows the state and the
  user's choice.
- Fingerprint: `fnv1a64Hex(argv.join("\0") + "\0" + normalizePath(cwd))` over the quote-aware split
  command plus normalized cwd. A changed **command/cwd/protocolVersion** is a refusal; a changed
  `agentName`/`agentVersion` is a warning, not a refusal. Store the components separately so the
  refusal reason can name the mismatch.
- Registry: `sessionStoreFolder/registry.json` (host-only, no tokens) with `sessionId →
  {harnessSessionId, deviceId, cwd, commandFingerprint, protocolVersion, lastSeq, state:
  "live"|"detached"|"dead", lastSeen}`; debounced writes (≤1 s), reconciled against records (drop
  rows with no record, adopt records with no row as `dead`).
- Resume/load/fresh decisions and outcomes are appended as `resume` entries; no decision is silent.
- The **digest** is a deterministic, bounded summary built only from the record:
  a fixed first line (`[Conversation digest — generated by Obsidian Chat from the stored record; not
  written by the model]`), the stored title/createdAt, the last **6** complete turns (user text
  ≤600 chars, final assistant text ≤900 chars, up to 8 tool lines), a deduped `Files touched:` line
  (≤30 paths), `Errors:` (≤5 safe messages), and `[end digest; truncated]` if any bound was hit;
  hard cap **8,000 characters**. Exclude timestamps other than createdAt, raw payloads, image bytes,
  permission messages, and credential-looking strings. Deliver it as one labelled `ContentBlock`
  prepended to the first prompt of the new session (not a separate visible user turn), record a
  `resume` entry `{method:"digest", chars}`, and label it in the transcript/raw view. The full
  transcript replay option uses the same mechanism with a 100,000-character prompt cap and a clearer
  label. Same record → byte-identical digest; a fixture snapshot test pins it. No model call.
- On `session/load` replay, the store reconciles: replayed history is not appended as new entries;
  only genuinely new live updates during the session are appended.

## 7. Legacy import (one-time migration)

- On first run after upgrade, scan the legacy chat folder for Markdown notes.
- Prefer the canonical transcript block (`oc-transcript-b64`) for exact messages/reasoning/activity;
  fall back to the legacy prose parser for notes without it, and skip unparseable notes.
- Each imported note becomes one record with a `meta` provenance entry; there is no harness session
  id, so its resume state is `digest-only`.
- Idempotency: `migration.json` records note path + content hash → imported sessionId; re-running
  imports nothing twice. Imported entries carry `imported: true, synthetic: true` (tool activity was
  presentation data, not raw ACP); record provenance `{originPath, originMtime, originHash}`; header
  `harnessSessionId: null`, `resume.state: "digest-only"`. Import is lossless for the note's content,
  not for raw ACP payloads that were never recorded — state this in the migration report.
- Originals are never modified or deleted; a summary (`imported N, skipped M`) is shown once and
  logged without content.
- The legacy note writer/parser is then removed from the runtime; only the import parser remains
  until the branch is complete, then it lives under `session/migrate.ts` as the single legacy reader.

## 8. Redaction and bounds

- Never stored: provider credentials, device tokens, MCP session tokens, raw image bytes (name/type
  only), or file content beyond what an ACP update itself carries and the tool-content bound below.
- Per-entry raw payload bound (plan constant, suggested 256 KB): oversized payloads are truncated
  with an explicit `truncated: true` marker and original size; the transcript never shows the
  truncated tail as if complete.
- Raw payloads in the record are local-only and never copied into the visible transcript or any
  error message.
- The store lives in the user's vault; it is not encrypted in v1 (documented limitation).
- Bounds: per-entry raw payload **256 KiB** with explicit `{truncated:true, originalBytes}`; the UI
  raw disclosure displays at most **16 KiB**; no rotation/compaction in v1; surface per-session size
  and warn at 50 MiB. A remote replay is capped at the last 20,000 entries; a full replay (no
  `sinceSeq`) still streams in order with backpressure.

## 9. Conformance checks (plan gates)

- One header per record; every line parses; sequences strictly increase; no rewrite of earlier
  lines (test: append 1,000 entries, assert file grows only); `turn` is the boundary entry kind and
  `turn_end` appears nowhere as a code identifier or record kind.
- Crash test: truncate the final line → reader returns all prior entries and marks a degraded tail;
  no session loss. Malformed interior line → skipped, rest preserved.
- Replay test: remote `session/load` with and without `sinceSeq` yields ordered, dedupable
  notifications and appends no entries.
- Digest snapshot is deterministic and bounded; resume-decision matrix covers all four states.
- Import: canonical-note and prose-note fixtures import once, losslessly, idempotently; originals
  unchanged; unparseable note reported and skipped.
